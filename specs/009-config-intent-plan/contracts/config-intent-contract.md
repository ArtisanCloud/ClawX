# 契约：配置意图判定与路由

## 目的
定义输入消息在“配置控制面”与“普通任务链路”之间的判定规则、优先级与降级语义。

## 1. 判定优先级
- `/config ...` 显式命令优先级最高，直接进入配置控制面。
- 非 `/config` 消息进入配置意图判定：
  - 明确命中配置意图：进入配置计划流程。
  - 低置信度：返回建议，不自动修改计划。
  - 未命中：回退普通任务链路。

## 2. 混合意图冲突契约
- 当单条消息同时命中“配置意图 + 任务意图”时，必须先返回澄清提示（示例：“请回复 配置 或 任务”）。
- 在用户明确“配置”前，不得修改 pending plan。
- 在用户明确“任务”前，不得继续执行配置链路。
- 澄清状态仅作用于当前会话；确认后必须清理该状态。

## 3. 低置信度契约
- 低置信度场景必须采用保守策略：
  - 不写配置文件
  - 不自动 patch pending plan
  - 返回可执行建议（示例：`/config plan ...`）

## 4. 错误契约
- 失败反馈必须可行动、可理解，至少覆盖：
  - 混合意图需澄清
  - 低置信度仅建议
  - 无待编辑计划
  - 补丁参数无效

## 5. 一致性要求
- 所有渠道共享同一配置意图语义。
- 渠道展示文案可不同，但判定结果与状态流转必须一致。
