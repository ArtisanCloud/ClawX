# 功能规格说明：Memory Context Layer（项目/Agent 记忆隔离）

**功能分支**: `006-memory-context-layer`  
**创建时间**: 2026-03-14  
**状态**: 草稿  
**输入**: 用户描述: "请根据 docs/guides/features/006-memory-context-layer/plan.md，实现独赢的 spec 文档。"

## 用户场景与测试（必填）

### 用户故事 1 - 项目记忆骨架与首轮加载（优先级：P1）

作为 ClawX 使用者，我希望在创建项目后自动具备可读可写的记忆文件，并在新会话首轮自动加载这些记忆，这样每次进入项目都能快速恢复上下文。

**为什么是这个优先级**: 这是记忆体系的基础闭环；没有初始化与加载，后续隔离与治理都无法成立。

**独立测试方式**: 创建新项目并启动新会话，验证项目目录下存在记忆骨架，且首轮执行前已加载基础记忆上下文。

**验收场景**:

1. **假如** 用户创建新项目，**当** 项目创建成功时，**那么** 系统应自动生成该项目的记忆骨架文件与日记目录。
2. **假如** 用户在该项目启动新会话，**当** 首轮任务执行前，**那么** 系统应按既定顺序加载基础记忆内容。
3. **假如** 记忆骨架文件部分缺失，**当** 用户触发会话，**那么** 系统应可自愈补齐或给出明确修复指引。

---

### 用户故事 2 - 同项目多 Agent 记忆隔离（优先级：P1）

作为运维与开发者，我希望同一个项目下不同 agent 拥有彼此隔离的私有记忆，避免多 agent 并发时出现记忆串读与污染。

**为什么是这个优先级**: 这是你关注的核心风险点；若 agent 私有记忆不隔离，会直接导致隐私和上下文串线。

**独立测试方式**: 在同一项目中让 Agent A 与 Agent B 并发执行任务，验证二者只能读取各自私有记忆，不能读取对方私有记忆。

**验收场景**:

1. **假如** Agent A 与 Agent B 同属一个项目，**当** A 写入私有记忆后，**那么** B 不得读取该私有记忆。
2. **假如** 两个 agent 并发执行任务，**当** 各自启动新会话，**那么** 系统应分别加载各自私有层与同一项目共享层。
3. **假如** 某 agent 私有目录缺失，**当** 该 agent 会话启动时，**那么** 系统应自动初始化该私有目录并继续执行。

---

### 用户故事 3 - 主会话与共享会话 ACL（优先级：P2）

作为用户，我希望主会话中的长期私有记忆不会泄露到共享频道或群聊会话，确保敏感偏好与个人信息不被错误加载。

**为什么是这个优先级**: 该能力直接影响隐私安全与平台可上线性。

**独立测试方式**: 对比“主会话”与“共享会话”加载清单，验证长期私有记忆仅在主会话可见。

**验收场景**:

1. **假如** 会话属于共享频道，**当** 系统加载记忆时，**那么** 必须跳过长期私有记忆文件。
2. **假如** 会话属于主会话，**当** 系统加载记忆时，**那么** 可以加载长期私有记忆文件。
3. **假如** ACL 规则冲突或判定失败，**当** 系统继续执行时，**那么** 应采用最小权限策略并记录审计信息。

---

### 用户故事 4 - 记忆写回与可观测治理（优先级：P2）

作为运维和高级用户，我希望能显式写入日记、汇总长期记忆并审计记忆状态，确保记忆体系可持续维护且可排障。

**为什么是这个优先级**: 没有写回与审计，记忆体系会快速失效且难以治理。

**独立测试方式**: 分别验证记忆记录、摘要汇总、审计输出三条路径可独立完成，且权限边界正确。

**验收场景**:

1. **假如** 用户记录记忆笔记，**当** 命令执行成功时，**那么** 笔记应写入当前作用域日记。
2. **假如** 用户触发长期记忆汇总，**当** 会话为主会话时，**那么** 汇总结果应写入长期记忆文件。
3. **假如** 用户执行记忆审计，**当** 审计完成时，**那么** 系统应输出缺失项、权限问题与隔离违规信息。

---

### 边界场景

- 当记忆文件体积过大时，系统如何截断并保持关键上下文优先。
- 当记忆文件损坏或格式异常时，系统如何降级执行并保留可追踪错误。
- 当项目被删除或切换时，历史记忆如何避免被误加载。
- 当 route key 变化导致会话入口变化时，记忆加载范围如何保持一致。
- 当 agent ID 变更或重命名时，私有记忆如何迁移或回收。

## 需求（必填）

### 功能需求

- **FR-001**: 系统必须为每个项目提供独立的记忆骨架与日记空间。
- **FR-002**: 系统必须在项目创建时自动初始化项目记忆骨架。
- **FR-003**: 系统必须在新会话首轮执行前加载记忆上下文。
- **FR-004**: 系统必须支持“项目共享记忆层”和“agent 私有记忆层”并存。
- **FR-005**: 系统必须保证同项目不同 agent 之间的私有记忆不可互读。
- **FR-006**: 系统必须保证跨项目记忆不可被加载。
- **FR-007**: 系统必须支持主会话与共享会话的差异化 ACL 规则。
- **FR-008**: 作为 FR-007 的强制子规则，系统必须默认禁止共享会话加载长期私有记忆。
- **FR-009**: 系统必须支持显式记录日记型记忆。
- **FR-010**: 系统必须支持将日记摘要汇总到长期记忆（受 ACL 约束）。
- **FR-011**: 系统必须支持记忆审计能力，输出缺失、权限与隔离异常。
- **FR-012**: 系统必须记录记忆加载清单的审计元信息（不暴露敏感正文）。
- **FR-013**: 系统必须在记忆加载失败时提供可追踪错误并保证主流程可降级。
- **FR-014**: 系统必须提供记忆骨架版本信息与漂移检测能力。
- **FR-015**: 系统必须支持在骨架缺失时自动补齐或提供修复动作。
- **FR-016**: 系统必须保证记忆写回默认落在当前 `agent + project` 私有作用域。
- **FR-017**: 系统必须支持显式共享写入（仅在允许时）。
- **FR-018**: 系统不得因记忆功能引入跨会话隐私泄露。
- **FR-019**: 系统不得破坏现有 `/new`、`/resume`、`/switch`、`/list`、`/current`、`/cancel` 语义。
- **FR-020**: 系统必须与现有 route/window/session/project 隔离模型保持一致。

### 关键实体（如涉及数据）

- **记忆配置档案（Memory Profile）**: 描述某作用域可加载的记忆文件集合、顺序、预算和 ACL 规则。
- **记忆条目（Memory Entry）**: 记忆文件中的最小可读写单元，包含时间、来源、内容摘要与可见性级别。
- **记忆作用域（Memory Scope）**: 由 `agent_id + project_id + route_key` 共同界定的加载与写回边界。
- **记忆审计记录（Memory Audit Record）**: 记录加载了哪些文件、哪些被拒绝、拒绝原因和修复建议。
- **记忆模板版本（Memory Template Version）**: 标记记忆骨架结构版本，用于初始化与漂移治理。

### 假设

- 当前系统仍以单节点部署为主，记忆文件采用本地文件存储。
- 项目与会话隔离能力已可用，可作为记忆隔离的前置条件。
- 默认项目为 `main`，并且至少存在一个可用 agent。
- 记忆内容默认以文本形式维护，后续可扩展结构化检索。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 100% 的新建项目在创建后自动具备记忆骨架文件与日记目录。
- **SC-002**: 95% 以上的新会话可在首轮执行前完成记忆加载且不中断主流程。
- **SC-003**: 100% 的同项目多 agent 并发场景中，不发生 agent 私有记忆串读。
- **SC-004**: 100% 的共享会话请求不会加载主会话长期私有记忆。
- **SC-005**: 100% 的记忆加载/拒绝事件具备可检索审计元信息。
- **SC-006**: 记忆加载阶段（不含后端执行）p95 额外开销小于 120ms。

### 统计口径

- 统计窗口：7 天滚动窗口。
- 样本量下限：每项成功标准不少于 200 次有效请求。
- 采集来源：集成测试日志、审计日志、人工验收脚本。
- 判定规则：任一 SC 未达标则不得进入发布候选。
