## 用户场景与测试（必填）

### 用户故事 1 - 自然语言优先的技能路由（优先级：P1）

作为管理员，我希望直接用自然语言描述需求（例如“帮我安装招投标抓取技能并绑定给 bid-all”），系统自动识别意图并执行对应技能操作，这样我不需要背大量命令。

**为什么是这个优先级**: 这是 Phase 7 的核心体验目标，决定系统是否从“命令驱动”升级为“语义驱动”。

**独立测试方式**: 在同一会话中分别发送自然语言与命令等价请求，验证均能产出同一类结构化 SkillAction 并完成执行。

**验收场景**:

1. **假如** 用户发送自然语言“给 bid-all 安装 pdf 抽取技能”，**当** LLM 路由成功时，**那么** 系统应生成结构化 action 并进入执行链路。
2. **假如** 用户发送 `/skill install ...`，**当** 指令解析成功时，**那么** 应映射到相同的 action schema。
3. **假如** LLM 置信度不足，**当** 请求高风险操作时，**那么** 系统应先澄清，不直接执行。

---

### 用户故事 2 - 技能注册与策略治理（优先级：P1）

作为平台所有者，我希望所有技能都有统一元数据与安装策略（来源、版本、风险级别、权限要求），这样我可以安全引入内建与第三方技能。

**为什么是这个优先级**: 没有治理层，第三方技能接入会直接带来供应链与权限风险。

**独立测试方式**: 安装内建技能、安装第三方技能、安装被策略禁止技能，验证策略决策与错误语义正确。

**验收场景**:

1. **假如** 技能来源不在白名单，**当** 用户请求安装时，**那么** 系统应拒绝并返回策略原因。
2. **假如** 技能版本未满足 pin/compat 约束，**当** 用户请求升级时，**那么** 系统应拒绝并提示可用版本。
3. **假如** 技能元数据缺失必填字段，**当** 注册或安装时，**那么** 系统应拒绝入库。

---

### 用户故事 3 - 多 Agent 技能共享与隔离（优先级：P1）

作为多项目使用者，我希望技能可以配置为全局共享、项目共享或单 Agent 私有，并有明确覆盖规则，这样不同智能体既可复用也可隔离。

**为什么是这个优先级**: 共享策略决定了多 Agent 场景的可维护性与可预测性。

**独立测试方式**: 分别绑定同名技能到 global/project/agent-local，验证解析优先级与运行结果符合预期。

**验收场景**:

1. **假如** 全局与 agent-local 同时存在同名技能，**当** agent 执行时，**那么** 应优先使用 agent-local。
2. **假如** 项目级绑定存在，**当** 同项目其他 agent 调用时，**那么** 应可见并可执行该技能。
3. **假如** 删除上层绑定，**当** 解析技能时，**那么** 系统应自动回落到下一层可用绑定。

---

### 用户故事 4 - 高风险技能的确认、审计与回放（优先级：P2）

作为运维与审计人员，我希望高风险技能执行必须确认，并能完整追踪“谁在何时以何参数执行了什么结果”，这样出现问题可快速回放定位。

**为什么是这个优先级**: 在 LLM 参与决策后，治理与可追溯是上线底线。

**独立测试方式**: 执行一次高风险技能请求（如删除目录），验证 confirm-first、审计记录、回放数据完整。

**验收场景**:

1. **假如** 技能标记为 high risk，**当** 用户请求执行时，**那么** 系统必须先确认再执行。
2. **假如** 用户拒绝确认，**当** 执行流程结束时，**那么** 不得产生副作用。
3. **假如** 执行成功或失败，**当** 查询审计时，**那么** 应包含结构化参数、决策来源、结果摘要和错误信息。

---

### 边界场景

- 同一消息命中多个候选技能时如何排序与澄清。
- skill catalog 过大时，如何在 token 预算内做上下文压缩。
- 第三方技能更新后 schema 变更导致旧绑定失效时如何降级。
- 高风险技能与低风险技能的组合调用如何逐步确认。
- 运行时缺失依赖（如二进制/网络）导致技能不可执行时的回退策略。

## 需求（必填）

### 功能需求

- **FR-001**: 系统必须提供统一 Skill Registry，管理 built-in 与 external 技能元数据。
- **FR-002**: 技能元数据必须至少包含 `skill_id`、`version`、`source`、`input_schema`、`risk_level`、`required_permissions`。
- **FR-003**: 系统必须支持技能来源策略（白名单/黑名单）并在安装时强制校验。
- **FR-004**: 系统必须支持版本治理策略（pin/compatible/latest）并在安装与升级时生效。
- **FR-005**: 系统必须支持三层技能绑定：`global`、`project`、`agent-local`。
- **FR-006**: 系统必须实现绑定解析优先级：`agent-local > project > global`。
- **FR-007**: 系统必须支持自然语言默认进入 LLM Skill Router，生成结构化 SkillAction。
- **FR-008**: 系统必须支持命令入口映射到同一 SkillAction schema，而非独立执行路径。
- **FR-009**: SkillAction 必须包含 `intent`、`skill_id`、`arguments`、`confidence`、`risk_level`、`requires_confirmation` 字段。
- **FR-010**: 系统必须在 SkillAction 执行前进行 schema 校验，校验失败不得执行。
- **FR-011**: 当置信度低于阈值时，系统必须进入澄清/建议流程，不得直接执行。
- **FR-012**: 高风险技能执行必须走 confirm-first，未确认不得执行。
- **FR-013**: 系统必须提供统一 Skill Executor，负责权限校验、参数校验、执行与结果标准化。
- **FR-014**: 系统必须将每次技能决策与执行写入审计日志，包含操作者、会话、来源、参数、结果。
- **FR-015**: 审计事件必须可回放到“决策输入 -> action -> 执行结果”链路。
- **FR-016**: 系统必须支持技能调用失败的可读错误语义（策略拒绝、权限不足、参数无效、运行失败、确认拒绝）。
- **FR-017**: 系统必须支持技能上下文压缩，将最近关键调用摘要化为结构化 digest。
- **FR-018**: 路由阶段必须使用 `message + context_digest + skill_catalog_digest` 作为决策输入。
- **FR-019**: 当摘要与原始执行轨迹不一致时，系统必须可重建摘要并记录重建原因。
- **FR-020**: 系统必须支持按 agent/project 查询当前有效技能视图（含来源层级与版本）。
- **FR-021**: 系统必须支持禁用技能，禁用后立即在解析与执行链路生效。
- **FR-022**: 系统必须支持对已绑定技能进行替换升级，并保留历史审计轨迹。
- **FR-023**: 系统必须保证普通任务在未命中技能意图时回退原有任务执行链路。
- **FR-024**: 系统必须提供与 `009-config-intent-plan` 的对接能力，以读取 agent 配置状态（workspace/profile/default）。
- **FR-025**: 系统必须明确禁止“通用插件市场”形态的无边界能力接入，仅允许受控白名单来源与受限能力清单中的技能被安装或执行。
- **FR-026**: 系统必须提供可配置的路由置信度阈值（`0.0~1.0`），默认值为 `0.70`，并在配置缺失时回退默认值。
- **FR-027**: 系统必须固定风险等级枚举为 `low|medium|high`，并满足：`high` 必须确认、`medium` 可按策略确认、`low` 默认免确认。
- **FR-028**: 系统必须引入结构化控制计划协议 `ControlPlan`（`type/intent/target/mode/risk/reason`），作为自然语言控制面动作的唯一自动执行输入。
- **FR-029**: 系统必须禁止从普通自然语言输出中通过正则/字符串匹配提取 `/command` 后自动执行。
- **FR-030**: 系统必须仅在 `ControlPlan` 通过 schema 与策略校验后执行控制动作；校验失败必须返回拒绝原因并记录审计。
- **FR-031**: 系统必须提供控制面动作白名单（如 `agent.use`、`agent.clear`、`config.apply`），白名单外意图不得自动执行。
- **FR-032**: 系统必须在控制动作执行后执行 `post-verify`，并以验证结果作为最终回复事实源（而非模型文本）。
- **FR-033**: 系统必须对控制动作提供幂等保障：重复请求命中同一目标状态时返回 `status=noop` 且不产生副作用。

### 关键实体（如涉及数据）

- **Skill Metadata**: 技能定义信息，包含能力描述、输入 schema、风险与权限要求。
- **Skill Policy**: 安装与升级治理规则，约束来源、版本、启用状态。
- **Skill Binding**: 技能与作用域（global/project/agent-local）的绑定关系。
- **Skill Action**: 路由层结构化决策结果，供执行层消费。
- **Skill Execution Record**: 技能执行记录，包含入参、出参摘要、耗时、状态与错误。
- **Skill Context Digest**: 技能调用压缩摘要，用于多轮语义路由上下文。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 自然语言技能请求中，结构化 action 解析成功率达到 90%+（基于契约样例集）。
- **SC-002**: 高风险技能未确认执行率为 0%。
- **SC-003**: 策略拒绝类请求的拒绝准确率达到 100%。
- **SC-004**: 技能执行审计覆盖率达到 100%（成功/失败/拒绝均记录）。
- **SC-005**: 三层绑定解析一致性达到 100%（契约测试覆盖冲突与回落场景）。
- **SC-006**: 低置信度请求误执行率低于 1%。
- **SC-007**: 在 skill catalog >= 200 条、近 50 条调用历史场景下，路由前摘要构建时间中位数不超过 300ms（单实例基线）。
- **SC-008**: 控制面自动执行路径中，因文本误解析导致的误执行率为 0%（仅 `ControlPlan` 可执行）。
